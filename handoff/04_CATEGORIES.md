# 04 · 카테고리 체계 + 빠른 입력 칩

> Cursor 작업 지시서 (4편). 지출 카테고리 분류와 입력 시 노출 방식.

---

## 1. 결정사항 (★ 사용자 확정)

- 지출 카테고리는 **9개 top × 평균 4개 sub** 2-depth 구조로 확정
- "RED" 카테고리 유지 (충동/후회 지출 강조 — 게임의 red 티어와 브랜드 일관)
- "커플" 카테고리는 **B안** 채택 — 현재 하위 1개("데이트비용")여도 유지. 추후 "선물", "기념일" 추가 여지 확보
- 빠른 입력 칩: **A안** — 최근/자주 사용 sub-카테고리 5개 + "더보기"
- "기타" sub는 데이터엔 있지만 **빠른 입력 칩에는 노출하지 않음** (더보기 화면에서만)
- 카테고리 모델: `{ top, sub }` 2-depth 분리 저장 (통계 집계 용이)

---

## 2. 카테고리 전체 구조 (확정)

| top         | sub                                          |
| ----------- | -------------------------------------------- |
| **RED**     | 커피, 택시, 충동구매, 기타                    |
| **생활**     | 배달, 외식, 의료, 필수품, 장보기, 기타        |
| **커플**     | 데이트비용, 기타                              |
| **고정**     | 통신, 보험, 기타                              |
| **주거**     | 월세, 대출이자, 기타                          |
| **자기개발** | 취미, 건강, 미용, 기타                        |
| **특별**     | 이벤트, 여행, 경조사, 기타                    |
| **반려동물** | 병원, 사료, 약값, 기타                        |
| **구독**     | OTT, 멤버십, 기타                             |

### 메모
- "RED"의 sub는 다른 카테고리와 의미 중첩 가능 (커피=생활/배달 vs RED/커피). 이건 **사용자 판단**으로 처리. 즉 사용자가 어디로 분류하느냐가 곧 그 거래의 감정 라벨.
- 입력 시 사용자에게 "이번 커피는 RED야? 생활이야?" 같은 분리 인지를 자연스럽게 유도 → 가계부의 자기성찰 가치.

## 3. 데이터 모델

```ts
type CategoryTop = "RED" | "생활" | "커플" | "고정" | "주거" | "자기개발" | "특별" | "반려동물" | "구독";

type Category = {
  top: CategoryTop;
  sub: string; // top별 정의된 sub 문자열 중 하나
};

type Transaction = {
  id: string;
  type: "spend" | "income" | "save";
  amount: number;
  category: Category;     // 지출에만 의무. 수입/저축은 별도 카테고리(섹션 6)
  date: string;           // ISO yyyy-mm-dd
  note?: string;
  createdAt: string;
};

type Favorite = {
  id: string;
  type: "spend" | "income" | "save";
  label: string;
  amount: number;
  categoryTop?: CategoryTop;  // type==="spend"인 경우만 의무
  categorySub?: string;
  usageCount: number;
  pinned?: boolean;
};
```

## 4. 빠른 입력 칩 (★ A안 적용)

### 노출 규칙
- 시트 열릴 때 **현재 type에 해당하는 거래 히스토리**를 분석해 **최근 30일 사용 빈도** 내림차순으로 **상위 5개 sub-카테고리**를 자동 선정
- **"기타" sub는 빠른 칩에서 제외** (히스토리에 있어도 패스)
- 5개가 안 채워지면 빈자리 채울 기본값 사용 (아래)
- 6번째 위치는 항상 `[더보기 ▾]` 버튼

### 데모/초기 기본값 (히스토리 없을 때)
```js
const DEFAULT_QUICK_SUBS = {
  spend: [
    { top: "RED",      sub: "커피" },
    { top: "생활",     sub: "배달" },
    { top: "커플",     sub: "데이트비용" },
    { top: "구독",     sub: "OTT" },
    { top: "주거",     sub: "월세" },
  ],
  income: [
    { top: "수입", sub: "급여" },
    { top: "수입", sub: "용돈" },
  ],
  save: [
    { top: "저축", sub: "비상금" },
    { top: "저축", sub: "주택청약" },
  ],
};
```

### 시각 표현
```
┌──────────────────────────────────────────────┐
│ [☕커피] [🍔배달] [💕데이트비용] [📺OTT] [🏠월세]  [더보기▾]
└──────────────────────────────────────────────┘
```
- top별 컬러 점 1개 (지름 6px) 좌측에 표시 — 출처 그룹 식별
- 칩 자체 색은 통일 (어느 그룹이든 같은 회색 톤). 점만 색.

### top별 컬러 (정해두기)
| top | 색 (제안) | 의도 |
|-----|-----------|------|
| RED      | #E54C5A | 게임 red 티어와 동일 |
| 생활     | #5BBE80 | 차분한 그린 |
| 커플     | #F08A4D | 따뜻한 오렌지 (감정성) |
| 고정     | #6E96FF | 의무·정기성의 블루 |
| 주거     | #B4A0E8 | 안정의 라벤더 |
| 자기개발 | #3FBBD8 | 성장·청량의 시안 |
| 특별     | #FFD66B | 이벤트의 옐로우 |
| 반려동물 | #E89AB4 | 따뜻한 핑크 |
| 구독     | #9DAEC4 | 차분한 그레이블루 |

> 게임 티어 컬러는 그대로 유지(blue/cyan/green/orange/red/save). 카테고리 컬러는 **분류 라벨용**으로 별개. 둘이 같이 보여도 헷갈리지 않게 카테고리 컬러는 6px 점 하나로만 노출.

## 5. "더보기" 화면 — 2-depth 풀 피커

### 진입
- 빠른 칩 마지막의 `[더보기 ▾]` 탭 → 시트 안에서 인라인 펼침 (시트 닫지 말 것)

### 구조
```
┌──────────────────────────────────────┐
│  ← 빠른 칩으로 돌아가기                │
├──────────────────────────────────────┤
│  ● RED      ● 생활    ● 커플          │   ← 9 top, 3x3 그리드 (점=top컬러)
│  ● 고정     ● 주거    ● 자기개발       │
│  ● 특별     ● 반려동물 ● 구독          │
├──────────────────────────────────────┤
│  [선택된 top의 sub 목록 가로 스크롤]    │
│   커피 · 택시 · 충동구매 · 기타         │
└──────────────────────────────────────┘
```

- top 탭 → 아래 sub 목록 갱신
- sub 탭 → `{ top, sub }` 확정 + 빠른 칩 영역 복귀
- 한 번 사용한 sub는 다음에 빠른 칩에 자동 등장

## 6. 수입·저축 카테고리

### 수입
- top 1개("수입") + sub 5개 — 깊이 1.5 정도, UI상은 그냥 5개 sub 칩 평면 노출
- 빠른 칩 기본: 급여, 용돈, 부수입, 환급

### 저축
- top 1개("저축") + sub 5개
- 빠른 칩 기본: 적금, 비상금, 주택청약, 투자

> 수입·저축은 분류가 단순해서 top 라벨 시각화 생략 가능.

## 7. 게임 메커니즘과의 연결

### 카테고리 컬러는 게임 블록 컬러와 별개
- 풀에서 블록이 떨어질 때 색은 **티어**(cyan/green/orange/red) 기준
- 카테고리 컬러는 헤더/통계/즐겨찾기 칩의 분류 라벨로만 사용
- 단, **RED 카테고리만큼은** 사용자가 RED로 분류한 거래의 풀 누적 때 살짝 다른 시각적 단서 줄 수 있음 (추후 검토 — 예: 풀 fragment에 미세 빨간 글로우)

### RED 카테고리 강조 (선택 사양)
- 통계 탭에 "이번 달 RED 지출 N건 / 합계 X원" 별도 카드
- 월말에 "RED 비중이 높은 달이었네요" 같은 회고 메시지
- 게임 메커니즘의 핵심 메시지("지출을 인식하라")와 직접 연결되는 장치

## 8. 마이그레이션 — 현재 프로토타입 → 이 사양

| 영역 | 변경 |
|------|------|
| `game-data.jsx` | `CATEGORIES` / `DEFAULT_QUICK_SUBS` / `TOP_COLORS` 상수 추가. `INITIAL_FAVORITES`를 `{ categoryTop, categorySub }` 모델로 변환 |
| `components.jsx` `BottomSheet` | quickCats 평면 배열 → `DEFAULT_QUICK_SUBS[type]` 사용. 칩에 컬러 점 추가. "더보기" 버튼 + 풀 피커 패널 |
| `components.jsx` `AppHeader` | (불변) |
| 저장 모델 | localStorage `chick_blocks/transactions` 에 `Transaction[]` 저장, category는 2-depth 객체 |
| 통계 탭 (추후) | top별 도넛 + sub별 막대 + RED 별도 카드 |

## 9. 검수 시나리오

1. 지출 칩 탭 → 시트 열림
2. 빠른 칩 5개 + 더보기 보임. 각 칩 좌측에 작은 컬러 점.
3. "💕 데이트비용" 칩 탭 → 카테고리 확정, 숫자패드 입력 가능
4. 더보기 탭 → 9개 top 그리드 인라인 펼침
5. "반려동물" 탭 → 하위 "병원/사료/약값" 가로 스크롤 (기타는 안 보임 또는 회색 처리)
6. "사료" 탭 → 빠른 칩 영역으로 복귀, "사료" 선택 확정 상태
7. 거래 확정 후 다음 입력 시 "사료"가 빠른 칩에 등장 (히스토리 학습)
