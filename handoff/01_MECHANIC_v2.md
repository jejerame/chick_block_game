# 병아리 블록 가계부 — 메커니즘 v2 (공중 부양 합산 시스템)

> Cursor 작업 지시서. 기존 `index.html` 프로토타입의 수동 컨트롤 방식을 **자동 합산·낙하** 방식으로 전면 교체.

---

## 핵심 한 줄
**지출은 "공중에서 합산되다가 임계 금액을 넘는 순간 블록으로 실체화되어 자동 낙하"하고, 저축은 사용자가 직접 배치한다.**

---

## 1. 세 단계 시각 흐름 (지출 블록)

### 1단계 · 공중 부양 (Pool 적립)
- 보드 **최상단(또는 상단 1~2행 영역)** 에 `<PoolZone>` 레이어 존재
- 자잘한 지출이 발생할 때마다 반투명한 작은 조각 (1셀짜리 알 모양)이 추가되어 **둥둥 떠다님**
- 조각들끼리 자석처럼 천천히 모이는 모션 → "합산되고 있다"는 시각 메타포
- 풀 옆/위에 진행 텍스트: `자잘지출 누적 28,500원 / 다음 블록까지 21,500원`

### 2단계 · 실체화 + 낙하 (Threshold 도달)
- 풀 누적액이 **다음 티어의 MAX**를 넘는 순간:
  - 떠 있던 조각들이 한 곳으로 빠르게 빨려들면서 **선명한 색의 4셀 테트로미노**로 변환 (0.3s)
  - 컬럼은 **랜덤** (0~COLS-1 중 블록 너비를 고려해서 안전한 범위에서 균등 랜덤)
  - 회전(rot) 0으로 시작
  - **자동 낙하** 시작 (예: 매 600ms마다 1행씩 하강 — 추후 설정값으로 빼기)
- 풀은 해당 임계값만큼 차감 (carry-over)

### 3단계 · 손맛 (낙하 중 회전만 허용)
- 블록이 떨어지는 동안 사용자가 할 수 있는 것:
  - **회전 (↑ / 우측 회전 버튼)** ✅
  - **즉시 드롭 (Space / DROP 버튼)** ✅
  - **좌/우 이동** ❌ — 컨트롤 자체 제거 / D-pad 좌우 버튼 삭제
- 회전 후에도 컬럼은 그대로. 회전으로 인해 벽 밖으로 나가면 회전 캔슬 (기본 SRS 무리 없이).

## 2. Pool 알고리즘 (의사 코드)

```js
const TIER_THRESHOLD = {
  cyan:   50_000,    // 1~5만 구간 — 풀이 5만 채우는 순간 발동
  green:  100_000,   // 5~10만 구간
  orange: 500_000,   // 10~50만 구간
  red:    Infinity,  // 단일 거래 >= 500_000원은 즉시 red로 단락(short-circuit)
};

function onSpend(amount) {
  // 1. 단일 큰 거래는 풀을 우회해 즉시 낙하
  if (amount >= 500_000) {
    spawnBlock("red");
    return;
  }
  // 2. 풀 누적
  pool += amount;

  // 3. 임계 초과 시: 가장 높이 넘은 티어 1개를 떨어뜨리고 차감, 반복
  while (true) {
    const tier = highestCrossedTier(pool); // cyan/green/orange 중 가장 큰 임계 넘은 것
    if (!tier) break;
    spawnBlock(tier);
    pool -= TIER_THRESHOLD[tier];
  }
}
```

규칙 요약:
- **풀은 절대 음수가 되지 않는다.** carry-over로 잔여만 다음 사이클로 이월.
- 한 번의 `onSpend()` 호출에서 여러 블록이 동시에 떨어질 수 있다 (예: 단일 60만 거래 → red 즉시 / 단일 12만 거래 → green 1개 + carry 2만).
- 블록은 큐(queue)로 쌓아뒀다가 **이전 블록 락 완료 후** 차례로 스폰. 동시에 여러 개가 화면에 있으면 안 됨.

## 3. 모양 ↔ 티어 매핑 (별도 파일 참조)

자세한 매핑은 `02_SHAPES.md` 참조. 요점:
- cyan → S 또는 Z (랜덤)
- green → T 또는 O (랜덤)
- orange → L 또는 J (랜덤)
- red → I (확정)

블록 색(테두리)은 기존 `TIER[tier].stroke` 그대로 사용. fill도 그대로.

## 4. 저축 블록 (지출과 비대칭)

- 저축은 자동 합산이 아니라 **사용자가 명시적으로 "저축 X원 했어요" 입력** 시 블록으로 즉시 등장
- 저축 블록은 **수동 조작**: ← → 이동, ↑ 회전, DROP 모두 허용
- 모양: 항상 O (안정의 사각형) 또는 T — 추후 결정. 우선 O 고정.
- 메시지: "지출은 못 막아도, 저축은 의식적으로 끼워 넣는다"

## 5. 라인 클리어 금지 + 한 칸 비우기 규칙 ⚠️ (가장 중요)

> **테트리스처럼 한 줄이 가득 차면 줄을 지우는 메커니즘은 절대 구현하지 말 것.**
> **그리고 애초에 한 줄이 가득 차는 상황도 만들지 말 것** — 락 직전 검사로 한 칸을 강제로 비운다.

### 왜?
이 앱은 "쌓인 지출이 보여야" 가계부로서 의미가 있음. 줄이 지워지면 한 달 누적이 사라져 본말전도. 더불어 "이번 달은 이만큼 썼다"는 시각적 압박감 자체가 핵심 메시지.

### 규칙 (지출·저축 블록 모두 동일하게 적용)
1. **`clearFullRows()` 류의 로직은 어디에도 만들지 않는다.** 라인이 가득 차도 그대로 둔다 (이론상).
2. **그러나 라인이 가득 차는 상황 자체를 사전 차단한다.** 다음 두 시점에서 검사:
   - **(a) 스폰 시점 — 컬럼 선택**: 랜덤으로 컬럼을 고르되, 그 컬럼에서 자동낙하 + 락 했을 때 어떤 행이라도 가득 차게 되면 그 컬럼은 후보에서 제외. 모든 컬럼이 가득 차게 만든다면 가장 빈 칸을 많이 남기는 컬럼 선택.
   - **(b) 락 시점 — 최종 보정**: 회전·드롭 결과 락 위치가 결정됐을 때, 락 후 가득 찰 행이 있는지 검사. 있으면:
     - 해당 행에서 락 셀 중 1개를 **희생 셀**로 지정해서 락하지 않고 사라지게 함 (`onSpendDodge()` 같은 콜백으로 "한 칸이 비워졌다"는 마이크로 토스트 표시 — `🐤 한 칸이 살아남았다`)
     - 또는 락 자체를 거부하고 한 칸 위에 올려두기 (선호: 첫 번째 방안이 더 게임적)
3. **저축 블록도 예외 없음.** 사용자가 좌우로 끼워 넣어서 한 줄을 채울 것 같으면 락 시점에 위 보정 적용. "한 줄 다 채우면 보너스" 같은 기존 테트리스 보상 일체 없음.

### 코드 위치 후보
```js
// 락 직전 검사
function wouldFillAnyRow(grid, lockCells) {
  // lockCells 적용 후 grid를 가상으로 만들고
  // 그 grid의 임의의 행이 COLS만큼 다 차는지 확인
}
function sacrificeCellIfNeeded(lockCells, grid) {
  // 가득 찰 행에 속한 lockCells 중 1개를 제거해서 반환
}
```

### 예외: "저축 보상" 액션은 별개
사용자가 명시적으로 "저축 한 줄 소진" 버튼을 눌렀을 때만 해당 행을 제거. 이건 라인 클리어와 다른 의도적 사용자 액션. 유지.

## 6. 수입 추가 시 인터랙션 ("슈우욱" 효과)

### 트리거
- 사용자가 "수입 +XX원" 추가 (앱에서 별도 UI 또는 외부 입력)

### 처리
1. `income` 상태 업데이트
2. **목표 지출선(`GOAL_ROW`) 위로 이동**: 새 GOAL_ROW = `floor(ROWS × expense / income)` 또는 더 단순하게 `GOAL_ROW -= n` (n은 income 변화량 비례). 음수/0 미만 가지 않도록 clamp.
3. **애니메이션**: 골 라인이 새 위치까지 0.5s ease-out으로 이동하고, 도착 직전 살짝 위로 튀었다가 내려앉는 **bounce** (translateY -4px → 0, 0.2s).
4. 이미 쌓여 있던 블록은 **그대로** (시각적으로 크기/위치 변화 없음). 라인만 올라가서 "위쪽 여유 공간"이 생기는 느낌.
5. 헤더의 백분율 칩, 계란판 알 개수, 분노 게이지도 동기 갱신.

### 구현 노트
- 라인은 board 안의 `<div class="goal-line">` (또는 가상 요소). top: `r * (CELL+GAP) + padding` 으로 계산.
- bounce는 CSS keyframes 한 번. JS는 위치만 set, 트랜지션·키프레임은 CSS가 처리.

## 7. 데이터/상태 변경 요약

### 추가
| 상태               | 타입       | 초기값 | 비고                       |
| ------------------ | ---------- | ------ | -------------------------- |
| `pool`             | number     | 0      | 자잘지출 누적              |
| `spawnQueue`       | array      | []     | 떨어뜨릴 블록 대기열       |
| `currentTier`      | string\|null | null | 활성 블록의 티어           |
| `goalRow`          | number     | 5      | 동적, income에 따라 변동   |

### 제거
- `PIECE_QUEUE` (사전 정의된 순서). 더 이상 사용 안 함. 또는 데모 시드용으로만 남김.
- `onMove(±1)` 좌우 이동 함수 — 지출 블록엔 호출되지 않도록. (저축 블록 한정으로만 노출)

### 유지
- `SHAPES`, `TIER`, `SAVE_TONE`, `makeInitGrid` 그대로
- 키보드: ↑ 회전, Space DROP만 살리고 ← → 는 저축 활성 시에만 동작

## 9. 마이그레이션 / 호환성

- 기존 `PIECE_QUEUE` 의존 컴포넌트(Controls의 NEXT 미리보기 등): 풀 시스템에선 의미가 약함. 대신 **"현재 풀 상태"** + **"다음 임계까지 남은 금액"** 으로 교체.
- 기존 active 블록 카드: 활성 블록이 있을 때만 보이도록 (없을 땐 풀 상태가 그 자리 차지).

## 10. 검토 시 시각 확인 포인트

Cursor가 작업 완료 후 사용자 확인용 시나리오:
1. 앱 진입 → 풀에 시드 금액 (예: 28,500원) 떠 있음
2. "+커피 5,000" 5번 클릭 → 풀이 53,500원 도달 → cyan 블록 1개 자동 실체화 → 랜덤 컬럼에서 자동 낙하 → 락
3. "+외식 70,000" 클릭 → 풀이 70,000원 → green 블록 자동 낙하
4. "+월세 600,000" 클릭 → 즉시 red(I) 블록 자동 낙하, 한 줄 통째로 점유. **단 라인 클리어는 발생하지 않음**.
5. "수입 +500,000" 클릭 → 골 라인 한 칸 위로 bounce, 헤더 칩 갱신
