# 03 · 입력 흐름 + 즐겨찾기 + 달력 탭 제거

> Cursor 작업 지시서 (3편). 메커니즘(01) / 모양 매핑(02) 결정 이후 추가된 입력 UX 사양.
> 한 줄 요약: **달력 탭 폐기 → 상단 수입/지출/저축 칩 탭 → 칩 위치에서 팝다운되는 반투명 시트 → 즐겨찾기 1탭으로 끝.**

---

## 1. 진입점 — 상단 칩 자체가 입력 트리거

- 헤더의 **수입 / 지출 / 저축** 칩 3개가 곧 입력구. 별도 + 버튼 / FAB / 입력 탭 없음.
- 각 칩은 종류를 의미함 → 시트가 열릴 때 종류 선택 단계 자체가 없음 (1단계 절약).
- 어포던스: 각 칩 라벨 옆에 작은 펄스 `+` 배지 (2.4s 호흡). 탭 가능함을 암시.
- 칩 탭 → 햅틱(가능하면) + 시트 등장.

### 칩 → 종류 매핑
| 칩 라벨 | sheetType | 시트 헤더 색 | 즐겨찾기 필터 |
|---------|-----------|--------------|---------------|
| 수입    | `income`  | 파스텔 블루  | type==="income" |
| 지출    | `spend`   | 파스텔 레드  | type==="spend"  |
| 저축    | `save`    | 파스텔 옐로우 | type==="save"   |

## 2. 시트 시각·애니메이션 (★ 사용자 확정)

### 위치
- **바텀시트 ✕** (아래에서 슬라이드업) ← 폐기
- **칩 바로 아래에서 팝다운** ⭕ — `align-items: flex-start`, `padding-top: 108px` (헤더 바로 아래)
- 가로: `max-width: 380px`, 폰 폭에 맞춰 거의 풀폭
- 세로: `max-height: calc(100% - 130px)` (헤더 + 일부 보드 보이도록)
- 시트 윗변에 작은 꼬리(△) — **탭한 칩 위치**(left 22% / 50% / 78%)로 이동해서 시각적 연결

### 애니메이션
- `transform-origin: 50% -20px` + `scale 0.88→1` + `translateY -14px→0` + `opacity 0→1`
- 지속: **220ms**, easing: `cubic-bezier(0.34, 1.56, 0.64, 1)` (살짝 통통 튀는 느낌)
- 닫힐 때도 동일 reverse (현재는 React unmount만 — 추후 exit 트랜지션 추가 권장)

### 농도 (★ 사용자 확정)
- **시트 자체: 92% 불투명** (linear-gradient + alpha)
- **백드롭: 32% 어둡게 + backdrop-filter: blur(3px)**
- 결과: 입력 중에도 보드가 흐릿하게 비침 → "게임이 멈춰 있고 입력 끝나면 곧 블록이 떨어진다"는 맥락 유지

### 닫는 방법
- 백드롭 탭
- 시트 우상단 ✕ 버튼
- 확인 버튼 누르면 자동 닫힘
- (모바일) 시트 위→아래 swipe — 추후 구현

## 3. 시트 콘텐츠 구성 (위→아래)

```
┌──────────────────────────────────────┐
│   지출 추가                       ✕   │  ← 헤더 (종류별 색)
├──────────────────────────────────────┤
│   ★ 즐겨찾기  탭=입력 · 길게=편집     │
│   [☕커피 5,500] [지하철 1,450] ...   │  ← 가로 스크롤 (사용횟수 내림차순)
├──────────────────────────────────────┤
│                       72,000원        │  ← 큰 금액 디스플레이 (우측 정렬)
├──────────────────────────────────────┤
│   [외식][교통][쇼핑][구독][편의·간식]   │  ← 카테고리 빠른 칩 (타입별 다름)
├──────────────────────────────────────┤
│   📅 오늘 · 5월 26일 (월) ▾           │  ← 날짜 칩 (오늘 기본)
├──────────────────────────────────────┤
│   1  2  3                            │
│   4  5  6                             │  ← 숫자 패드 3×4
│   7  8  9                             │
│   00 0  ⌫                             │
├──────────────────────────────────────┤
│   ▼ 72,000원 추가                    │  ← 확인 버튼 (종류 색, 풀폭)
└──────────────────────────────────────┘
```

### 카테고리 빠른 칩 — 타입별 기본값
- spend: `["외식", "교통", "쇼핑", "구독", "편의·간식"]`
- income: `["급여", "용돈", "부수입", "환급"]`
- save: `["적금", "비상금", "투자", "주택청약"]`

### 날짜 칩
- 시트 열릴 때 **오늘 자동 선택**.
- 칩 탭 시 인라인으로 **7일 가로 스크롤** 펼침 (오늘 -3 ~ +3). 그 외 날짜는 **"다른 날짜"** 버튼 → 네이티브 `input[type=date]` 미니 달력 (`components.jsx` `BottomSheet`)
- 시트 안에 통째 달력 박지 말 것 ✕

### 숫자 패드
- 3×4: `1-9`, `00`, `0`, `⌫`
- `00`은 큰 금액 입력 가속 (예: 50,000 → "5" "00" "00")
- `⌫`: 한 자리 삭제
- 키 누름마다 햅틱 + 살짝 transform 피드백

## 4. 즐겨찾기 시스템 (★ 사용자 요청)

### 왜 중요한가
즐겨찾기 = **반복되는 자잘 지출**(커피, 지하철). 이건 정확히 풀에 누적되는 거래들 → 즐겨찾기로 입력 마찰 ↓ → 풀이 빨리 차오름 → 블록 실체화 빈도 ↑ → "자잘 지출이 큰 블록으로 합쳐진다"는 핵심 메시지가 더 강해짐. **편의기능이 아니라 게임 메커니즘의 동력**.

### 데이터 모델
```ts
type Favorite = {
  id: string;             // "fs1" 등 유니크
  type: "spend" | "income" | "save";
  label: string;          // "커피"
  amount: number;         // 5500
  category: string;       // "편의·간식"
  usageCount: number;     // 자동 증가
  pinned?: boolean;       // 사용자가 명시적으로 고정 (추후)
  createdAt?: string;
};
```

### 초기 시드 (현재 프로토타입)
```js
const INITIAL_FAVORITES = [
  { id: "fs1", type: "spend",  label: "커피",     amount:    5_500, category: "편의·간식", usageCount: 24 },
  { id: "fs2", type: "spend",  label: "지하철",   amount:    1_450, category: "교통",       usageCount: 18 },
  { id: "fs3", type: "spend",  label: "점심",     amount:   12_000, category: "외식",       usageCount: 15 },
  { id: "fs4", type: "spend",  label: "편의점",   amount:    4_200, category: "편의·간식", usageCount: 11 },
  { id: "fs5", type: "spend",  label: "맥주",     amount:   18_000, category: "외식",       usageCount:  6 },
  { id: "fi1", type: "income", label: "월급",     amount: 3_200_000, category: "급여",      usageCount:  1 },
  { id: "fi2", type: "income", label: "용돈",     amount:   100_000, category: "기타수입",  usageCount:  3 },
  { id: "fv1", type: "save",   label: "비상금",   amount:    30_000, category: "비상금",    usageCount:  8 },
  { id: "fv2", type: "save",   label: "주택청약", amount:   100_000, category: "적금",       usageCount: 12 },
];
```

### 정렬·노출 규칙
1. **시트 열릴 때**: 현재 type 필터 → `usageCount` 내림차순 정렬
2. **`usageCount >= 3`** (`FAV_AUTO_PIN`) 인 즐겨찾기에는 📌 아이콘 자동 표시 (사용자가 명시적으로 핀 박은 것 외에도 시각적 강조)
3. **0개일 때**: "★ 자주 쓰는 금액을 저장해두면 1탭으로 입력" 안내 + `[+]` 추가 버튼만 노출
4. 최대 노출: 가로 스크롤이라 무제한, but 권장 화면 노출 5-7개

### 인터랙션
| 액션 | 동작 |
|------|------|
| **단탭** | 금액·카테고리 자동 채움 + **400ms 후 자동 확정** (시트 닫힘 + 거래 등록) |
| **길게 누르기 (550ms)** | 이름·금액 수정 / 즐겨찾기 삭제 메뉴 (`BottomSheet` `fav-menu`) |
| **+ 버튼** | 새 즐겨찾기 만들기 — 현재 입력 중인 값(금액·카테고리)을 즐겨찾기로 저장하는 다이얼로그 |
| **사용 시 usageCount +1** | 자동 갱신, 다음에 열릴 때 정렬 반영 |

### 자동 추천 (`FAV_SUGGEST_COUNT` = 3)
사용자가 **같은 금액 + 같은 카테고리**를 3회 이상 거래 내역에 쌓인 뒤, 시트에서 동일 조합 입력 시:
- 상단 배너: `★ ○○ N원을 자주 쓰시네요 · 즐겨찾기에 저장할까요?` + **[무시]**
- **즐겨찾기 저장 토글이 ★ on으로 시작** (끌 수 있음)
- 무시 시 `localStorage` `chick.favSuggestDismiss`에 서명 저장 → 동일 조합 재추천 안 함

### "방금 입력한 거래 → 즐겨찾기 저장" — 인라인 토글 (★ 사용자 확정)
거래 확정 **전에** 시트 안에서 결정하는 방식.

#### 위치
- 시트 안, **숫자패드와 확인 버튼 사이**의 점선 박스
- 항상 노출 (시트의 일부)

#### 동작
- 기본 상태: ☆ + "다음에도 빠르게 입력 · 즐겨찾기에 저장" (회색 점선 박스)
- 탭 시 토글: ★ + "즐겨찾기에 저장됨 · 다음에 1탭으로 입력" (노란 실선 박스, ★ 살짝 회전)
- **카테고리 미선택 또는 "기타"이면 자동 비활성** (즐겨찾기 의미 없음)
- 토글 on 상태로 확인 버튼 누르면 → 거래 등록 + 즐겨찾기에 즉시 추가 (label = `categorySub`, usageCount = 1)
- 즐겨찾기 칩에서 1탭으로 들어와 입력한 경우엔 토글이 자동으로 숨겨짐 (이미 즐겨찾기에 있으니)

#### 왜 토스트가 아니라 인라인인가
이전 안: 시트 닫힌 뒤 화면 하단 토스트 (3.5초)
- 문제 1: 시트와 시각적으로 분리되어 있어서 무엇이 방금 일어났는지 연결이 약함
- 문제 2: 사용자 주의가 다른 곳(보드의 블록 낙하 등)으로 갔다가 못 보고 놓침
- 문제 3: 결정 시점이 입력 직후가 아닌 "이미 끝난 뒤"라 결정 모멘텀이 떨어짐

인라인 토글: 입력 중 같은 화면에서 결정 → 가장 자연스러운 흐름.

#### 자동 추천 (구현됨)
거래 내역에 같은 `{ type, amount, categorySub }`가 **3건 이상**이고 즐겨찾기에 없으면, 시트에서 해당 조합 입력 시 토글 **★ on** + 배너. **무시**로 dismiss.

### 데이터 저장
- 클라이언트 localStorage (서버 연동 전): `key: "chick_blocks/favorites"`
- 백엔드 도입 후: 사용자 계정에 묶음 + 디바이스간 동기화

## 5. 입력 → 게임 메커니즘 연결 ⭐

### 지출 입력 (sheetType="spend")
1. 시트 닫힘 (220ms)
2. 0.3s 대기
3. `onSpend(amount, category)` 호출 → 풀에 누적 (`01_MECHANIC_v2.md` 섹션 2 참조)
4. 임계 도달 시 블록 자동 실체화 → 낙하

### 수입 입력 (sheetType="income")
1. 시트 닫힘
2. `setIncome(income + amount)`
3. 목표 지출선이 **위로 한 칸 bounce 애니메이션** (`01_MECHANIC_v2.md` 섹션 6 참조)
4. 헤더 칩 / 분노 게이지 / 계란판 모두 동기 재계산

### 저축 입력 (sheetType="save")
**현재 프로토타입 (간이판)**: `savingsBucket`에 단순 누적 → 헤더의 saving 칩에 합산 표시
**최종 사양 (Cursor 구현)**:
1. 시트 닫힘
2. 보드 상단에 **노란 저축 블록(O 모양)** 활성 상태로 등장
3. **사용자가 직접 ← → ↑ ↓ DROP으로 수동 배치** (지출과 비대칭 — `01_MECHANIC_v2.md` 섹션 4 참조)
4. 락 시 saving에 가산

> 비대칭 컨트롤이 핵심 메시지: **지출은 못 막아도, 저축은 의식적으로 끼워 넣는다.**

## 9. Cursor 검수 시 확인 시나리오

1. 앱 진입 → 헤더 3칩에 펄스 `+` 어포던스 보임
2. **지출 칩** 탭 → 칩 아래로 시트 팝다운, 시트 위에 △ 꼬리가 가운데 칩 위치(50%)에 정렬
3. ★커피 즐겨찾기 탭 → 시트가 0.4s 후 자동 닫히며 풀 +5,500원 누적
4. 시트 다시 열고 숫자패드로 22,000 입력 → 카테고리 "교통" 칩 탭 → 확인 → 풀에 +22,000 + 누적 50,000 넘으면 cyan 블록 자동 낙하
5. **수입 칩** 탭 → 시트 △꼬리 좌측 22%로 이동, 색은 파스텔 블루 → 50만 입력 → 골 라인 위로 bounce
6. **저축 칩** 탭 → △꼬리 우측 78%, 색은 파스텔 옐로우 → 30,000 입력 → (최종 사양에선) 노란 O 블록 활성 등장 → 사용자 수동 배치
7. bottom-nav 3탭 확인
8. 시트 백드롭 클릭 → 닫힘. 시트 안 ✕ 클릭 → 닫힘.
