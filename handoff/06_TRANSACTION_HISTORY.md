# 06 · 항목 보기/수정 (거래 내역 관리)

> Cursor 작업 지시서 (6편). 이미 입력한 거래를 보고, 수정하고, 삭제하는 흐름.

---

## 1. 결정사항 (★ 사용자 확정)

- 진입점: **우측 RAGE 패널의 "지출 TOP 3" 바로 아래에 "🐤 항목 보기/수정 →" 미니 버튼**
- 길게 누르기 같은 숨겨진 제스처 사용 X — **시각적 어포던스가 명확한 진입점**으로 결정
- 진입점은 지출 맥락이지만 막상 열리면 **지출/수입/저축 3종 다 관리 가능** (필터 탭)
- 편집 시트는 **입력 시트 재활용** + 삭제 버튼 추가
- 보드/풀 recompute는 Cursor 구현 영역 (프로토타입은 합계 수치만 동기화)

---

## 2. 진입점 디자인

### 위치
`AngerRoomPanel` 내부, "지출 TOP 3" 리스트 마지막 행 바로 아래.

```
┌────────────────────┐
│ ● 지출 TOP 3        │
│ ─────────────       │
│ 1 외식·배달  48.2만 │
│ 2 구독·멤버십 31.8만│
│ 3 택시·교통  24.6만 │
│ ─────────────       │
│ 🐤 항목 보기/수정 → │  ← 진입점
└────────────────────┘
```

### 시각
- 노란 점선 박스, 약간의 hover lift
- 좌측: 노란 병아리 아이콘 (저축 병아리 PNG 작게)
- 중앙: "항목 보기/수정" (한국어, 11px 정도)
- 우측: `→` 화살표 (2.6s 흔들림 애니메이션, "여기 누르세요" 어포던스)

### 카피 결정
- 텍스트: **"항목 보기/수정"** (사용자 확정)
- 이전 안이었던 "지출 보기/수정" / "거래 보기/수정"보다 모든 종류(수입/저축 포함) 포괄
- 영문 표현 X (앱 톤 일관)

## 3. 항목 리스트 시트

### 진입
TOP 3 아래 진입점 탭 → **하단에서 슬라이드업** (입력 시트와 같은 패턴이지만 더 큼: 화면의 84%)

### 구조
```
┌──────────────────────────────────────┐
│  항목 보기/수정                    ✕  │
├──────────────────────────────────────┤
│  [지출 8] [수입 1] [저축 2]           │  ← 필터 탭 + 개수 뱃지
├──────────────────────────────────────┤
│  지출 총합              742,200원      │  ← 필터별 합계
├──────────────────────────────────────┤
│  5월 26일 (월)                        │  ← 날짜 그룹 sticky 헤더
│  ┌────────────────────────────────┐ │
│  │● 커피      RED        -5,500 ›│ │  ← 행 클릭 → 편집
│  │● 외식      생활      -12,000 ›│ │
│  │● 배달      생활      -22,000 ›│ │
│  └────────────────────────────────┘ │
│  5월 25일 (일)                        │
│  ...                                  │
└──────────────────────────────────────┘
```

### 필터 탭
- 3종: 지출(빨강) / 수입(파랑) / 저축(노랑)
- 활성 탭: 해당 색 보더 + 강조 폰트
- 옆에 작은 개수 뱃지

### 날짜 그룹 헤더
- `position: sticky; top: 0` — 스크롤 시 헤더만 따라옴
- 폰트 작고 회색, 모노 폰트로 날짜 강조 (예: "5월 26일 (월)")

### 각 항목 행
- 좌: 카테고리 top 컬러 점 (8px, 글로우)
- 중: sub 카테고리 (큰 폰트) + top 카테고리 (작은 회색)
- 우: 금액 (지출은 `-` prefix, 수입/저축은 `+`)
- 끝: `›` chevron — 클릭 가능 표시
- hover: 살짝 우측으로 밀려나고 배경 밝아짐

### 빈 상태
"이 분류에 거래가 없어요" + 회색 ghost 병아리 일러스트

## 4. 편집 시트 (입력 시트 재활용)

### 핵심 원칙
**입력 시트와 같은 컴포넌트를 재활용한다.** 새로 만들지 않음.

차이점은 `editing` prop 유무로 분기:

| 항목 | 입력 모드 | 편집 모드 |
|------|----------|----------|
| 시트 제목 | "지출 추가" | "지출 수정" |
| 즐겨찾기 영역 | 노출 | **숨김** (편집할 거래는 이미 결정됨) |
| 원본 배너 | 없음 | **"📝 원본: 5월 26일 · 5,500원 · 커피"** 회색 행 추가 |
| 카테고리 미리 채움 | 없음 | `editing.categoryTop` / `editing.categorySub` 자동 선택 |
| 금액 미리 채움 | 0 | `editing.amount` |
| 즐겨찾기 저장 토글 | 노출 | (현재) 노출되지만 의미 다름 — 추후 검토 |
| 확인 버튼 라벨 | "추가" | "수정 저장" |
| 삭제 버튼 | 없음 | 🗑️ **노출** (하단) |

### 삭제 흐름 (실수 방지)
- 🗑️ 한 번 클릭 → 버튼이 빨갛게 변하면서 흔들림 + "⚠️ 한 번 더 눌러 삭제 확정" 텍스트
- 한 번 더 클릭 → 실제 삭제 (`onDelete(id)` 호출)
- 시트 닫으면 confirm 상태 리셋
- 단계별 확정 = 모달 다이얼로그 없이 in-place로 안전성 확보

## 5. 데이터 모델

```ts
type Transaction = {
  id: string;             // "t_타임스탬프"
  date: string;           // "2026-05-26" (ISO date)
  type: "spend" | "income" | "save";
  amount: number;
  categoryTop: string;    // "RED" | "생활" | ... | "수입" | "저축"
  categorySub: string;    // "커피" | "외식" | "월세" | ...
  createdAt: number;      // 타임스탬프
  // 추후: note?, paymentMethod?, attachment?
};
```

### 정렬
- 날짜 내림차순 (최신이 위)
- 같은 날짜는 `createdAt` 내림차순

### 저장
- 클라이언트 localStorage: `chick_blocks/transactions`
- 백엔드 도입 후 동기화

## 6. ⚠️ 보드/풀 Recompute (Cursor 핵심 작업)

거래 수정/삭제 시 **그 시점부터의 풀·보드 상태를 다시 계산**해야 정합성 유지.

### 왜 필요한가
- 자잘한 지출(예: 5,000원)은 단독 블록이 아니라 **풀에 누적**되어 다른 거래들과 합쳐져 블록 1개가 됨
- 따라서 "이 거래에 해당하는 블록"이 1:1로 존재하지 않음
- 거래를 빼면 그 시점 이후의 풀 흐름 전체가 달라짐 → 보드 결과 자체가 달라져야 함

### 권장 구현
```js
function deriveBoardState(transactions, baseGrid, income) {
  // 1. 정렬: createdAt 오름차순
  const sorted = [...transactions].sort((a, b) => a.createdAt - b.createdAt);
  // 2. 풀 시뮬레이션
  let pool = 0;
  const blockEvents = [];
  for (const tx of sorted) {
    if (tx.type !== "spend") continue;
    if (tx.amount >= TIER_THRESHOLD.orange) {
      blockEvents.push({ tier: "red", amount: tx.amount });
      continue;
    }
    pool += tx.amount;
    while (true) {
      const tier = highestCrossedTier(pool);
      if (!tier) break;
      blockEvents.push({ tier, amount: TIER_THRESHOLD[tier] });
      pool -= TIER_THRESHOLD[tier];
    }
  }
  // 3. blockEvents를 보드에 차례로 락 (랜덤 컬럼 결정은 deterministic seed 사용 권장)
  return placeBlocks(blockEvents, baseGrid);
}
```

### Deterministic 보장
- 컬럼 랜덤 결정 시 `seedrandom(transactionId)` 같은 방식으로 **재계산해도 같은 결과** 나오게
- 그렇지 않으면 수정할 때마다 보드 모양이 휙휙 바뀌어 사용자가 혼란

### 프로토타입에서는?
- 합계 수치(income/expense/savingsBucket)만 동기화. 보드는 안 건드림.
- 정식 구현은 Cursor 영역.
